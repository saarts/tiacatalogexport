# Verify against an installed Siemens V20 system

The Windows build uses the local .NET Framework Openness assembly at runtime. It checks for the exact callable signatures it uses and reports missing members. It has been compiled on Linux and tested with a substitute catalog. The live API and Siemens documentation were unavailable in the development environment.

Consult the official V20 Openness manual for the catalog search and connection contracts. [Siemens TIA Portal V20 Openness documentation](https://docs.tia.siemens.cloud/r/en-us/v20/tia-portal-openness-api-for-automation-of-engineering-workflows)

1. Run `HardwareCatalogExporter.exe --inspect-api` on the Windows host. Record the assembly location, product version, declared `Find` overloads and parameter names, and exposed catalog item properties. Compare them with the V20 manual. The adapter reads the known item properties when present and retains additional scalar properties under `additional_metadata`. Complex properties are visible in inspection output and need verified mappings before export.
2. Open V20 and run `--list-processes`. Attach to the reported PID, first without a project if the API permits it, and run an export. Confirm the process remains open after disconnect. Repeat with an existing project and check the reported project name. Start both owned instance modes and check their PIDs and cleanup when their sessions are disposed.
3. Compare the empty-search output with the documented scope of `Find(string)`. Compare several targeted `--search` results against the empty-search result by exact identifier and catalog version. Include installed HSPs and project-associated GSD or GSDML entries where applicable. A successful sample comparison alone cannot establish completeness. If the empty search is scoped or excludes entries, use the V20 manual to identify the supported enumeration strategy and implement it before claiming full catalog coverage. The current app offers individual searches and retains the coverage warning.
4. Compare representative exported values with the API for multiple versions of the same article and both S7-1200 generations. Check exact and normalized identifiers independently. Confirm the meaning and exposed shape of `CatalogPath`, `Version`, hardware revisions and firmware-related properties before expanding mappings.
5. Check whether any reported `Find` overload explicitly documents CPU compatibility semantics. A two-string signature alone is insufficient. Verify it with two versions of the same CPU and known compatible and incompatible entries. Keep catalog relationships separate from configurability in a specific slot, electrical restrictions and module counts. The exporter currently emits no compatibility database.

When testing an unauthorized application, use the Siemens authorization UI in the same Windows session. The exporter leaves process authorization and group membership under Siemens and Windows control.

## Diagnose a slow catalog extraction

The GUI displays the current extraction stage, elapsed time and row count during enumeration. The CLI reports the same stages with `--verbose`. Visual Studio messages about `FunctionFromSTA` threads exiting with code 0 are debugger output. Use the exporter's stage and error messages to locate the delay.

Try a narrow API search, such as a known article number. If the stage stays at **Waiting for TIA Portal catalog search**, the Siemens `Find(string)` call has yet to return. If it shows **Reading catalog rows**, the exporter is enumerating results and reading item properties. **Cancel extraction** takes effect when the current Siemens call returns. Rows appear in the grid in batches as the exporter reads them. Cancellation keeps the rows read so far available for export and marks the result as partial. If the new query produced no rows before cancellation, the previously loaded grid stays available.
